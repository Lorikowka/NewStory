# Kotlin-сценарии: первый прототип

Пользовательский язык проекта — Kotlin Script (`.se.kts`). Java 17 остаётся языком ядра. Пример находится в `samples/kotlin/chapter_01.se.kts`: объявление StoryNPC, две реплики и `wait(2.seconds)` без обёртки `story(...)`. Файл собирается в тот же immutable Story Graph, который исполняет runtime. `wait` создаёт таймер, не усыпляет игровой поток.

Проверка headless из корня проекта:

```powershell
.\gradlew.bat -p modules :engine-script-compiler:run --args="../../samples/kotlin/chapter_01.se.kts story:chapter_01"
.\gradlew.bat -p modules :engine-script-compiler:test
```

Успешная headless-проверка выводит `VALID story:chapter_01 <hash> nodes=4`. При запуске мода пример копируется в `gameDir/storyengine/scripts/chapter_01.se.kts`, если файла там ещё нет. При открытии мира сервер компилирует до 32 локальных `.se.kts` из этой папки. В мире с разрешёнными командами: `/story list`, `/story validate local:chapter_01`, `/story start local:chapter_01`; для остановки — `/story stop`. Изменения файлов вступают в силу после успешной /story reload или повторного открытия мира. Ошибка одного файла записывается в лог, остальные истории загружаются. `scripts/temple.json` и `/story chatdemo` продолжают работать.

После редактирования файлов выполните `/story reload` (права оператора, уровень 2). Компиляция проходит в фоне; результат применяется серверным потоком. Если хотя бы один файл неверен, весь прежний каталог сохраняется, ошибки записываются в серверный лог. При успехе удалённые файлы исчезают из каталога, новые экземпляры используют новые графы, а уже запущенные продолжают прежние. Повторная reload до завершения предыдущей отклоняется. Команда перезагружает только Kotlin-файлы; JSON temple.json по-прежнему читается при открытии мира.

Скрипт выполняется как доверенный локальный Kotlin-код во время построения графа. Не загружайте неизвестные `.se.kts`: изоляция и политика разрешений ещё не реализованы. Время первой компиляции может заметно задержать открытие мира. Фоновая reload не ограничивает время исполнения пользовательского кода; выход из мира отбрасывает её результат, но не гарантирует остановку произвольного Kotlin-кода. Для изображения головы Орена положите `oren.png` в `gameDir/storyengine/assets/heads/`; без файла появится стандартная голова.

## Перезагрузка и игровые события

`/story reload` компилирует локальные Kotlin-сценарии в фоне. Новый каталог применяется целиком; любая ошибка сохраняет прежний каталог. Активные истории продолжают прежние графы. JSON temple.json эта команда не перезагружает.

В Kotlin используйте `awaitEvent("engine:block_interact")`: после активации ожидания правый клик основной рукой по любому блоку продолжает историю игрока. Событие не сохраняется для будущих ожиданий. Пример: `samples/kotlin/interaction.se.kts`. Скопируйте его в `run/storyengine/scripts/`, выполните `/story reload`, затем `/story start local:interaction`. Для headless-проверки можно отправить `/story signal engine:block_interact`.


## Режимы реплик

DSL поддерживает `oren.say("Текст")`, `oren.think("Мысль")` и `oren.whisper("Тише")`. Режим хранится в графе и передаётся клиенту. SAY показывает обычный текст, THOUGHT — текст в круглых скобках, WHISPER — пометку «(шёпотом)». Имя и квадратные скобки сохраняют цвет персонажа, текст — белый. Пример двух персонажей: samples/kotlin/dialogue_modes.se.kts. Клиент и сервер должны использовать одинаковую версию мода: текущая версия narrative-протокола — 4.

## Проверка текущего файла без активации

`/story validate local:chapter_01` компилирует текущее содержимое chapter_01.se.kts в фоне и показывает источник, hash либо ошибку со строкой. Команда не заменяет рабочую версию: после успешной проверки используйте /story reload для активации. Можно проверить новый файл до его появления в /story list. Валидация и reload выполняются по одной; повторный запрос отклоняется до окончания текущего. Как и reload, проверка исполняет доверенный Kotlin-код при построении графа.

## Режимы портрета

StoryNPC принимает необязательный пятый аргумент — `StoryDefinition.PortraitMode`:

- `CUSTOM_TEXTURE` (по умолчанию): загрузить portraitId.png из assets/heads, при отсутствии или ошибке показать стандартную голову.
- `NONE`: не загружать и не рисовать голову, убрать отступ для неё.
- `FALLBACK`: всегда показать стандартную голову, не читать локальный PNG.

Пример: `class Voice : StoryNPC("story:voice", "Голос", 0xBBBBBB, "voice", PortraitMode.NONE)`. Полный пример — samples/kotlin/portrait_modes.se.kts. Старый конструктор с четырьмя аргументами сохраняется. AUTO_RENDER пока не реализован. Режим передаётся отдельным enum в сетевом пакете, текущая версия протокола — 4.

Kotlin host и compiler загружаются отдельным classloader из вложенных библиотек META-INF/storyengine-libraries. Это отделяет зависимости от модульной системы Forge и не ограничивает права доверенного пользовательского Kotlin-кода. Java API и граф общие с модом.
