# Сюжетный чат: найденные ориентиры

Пожелание пользователя: сюжетные реплики должны располагаться по центру; ориентир — StoryTelling, запасной пример — TellingEngine.

## StoryTelling (основной ориентир)

В originalStoryTelling найдены MessageOverlay.class и Message.class в com/storyteam/storytelling/client/content/overlays. Java-исходников этих классов нет; поведение проверено через javap, без изменения соседнего проекта.

MessageOverlay реализует IGuiOverlay. Это самостоятельная плашка, а не стандартный чат. Горизонтальное положение: screenWidth / 2 - boxWidth / 2. Вертикально плашка находится снизу: screenHeight - bottomMargin - boxHeight. Отступ обычно 50 GUI-пикселей, в cutscene 25, при флаге SV 60. Текст переносится на ширину до 60% GUI-экрана. Состав текста: speakerName + flavor + двоеточие + message. Подложка чёрная, с прозрачностью 0.5 * текущая alpha. Предусмотрены иконка, время показа и alpha; при открытом Screen обычный render возвращается без отрисовки.

Важно: центрируется вся плашка по горизонтали, а не каждая строка и не блок относительно середины высоты экрана.

## TellingEngine (дополнительный читаемый пример)

src/main/java/com/storyengine/client/NarrativeOverlay.java: плашка по центру снизу, 60 GUI-пикселей над нижним краем; перенос 260 px, padding 6, line height 10, иконки 16 px, фон 0xB0101010. Имя показывается сразу, текст раскрывается постепенно. NarrativeChatManager управляет очередью и временем показа. S2CStoryChatPacket передаёт реплику клиенту.

## Применение к NewStory

Сюжетные реплики должны идти через отдельный клиентский overlay, а служебные ответы /story — оставаться в обычном чате. За основу расположения берём StoryTelling. Реализацию адаптируем к Forge 1.20.1 и GuiGraphics; ядро продолжает отдавать декларативные эффекты и не импортирует клиентский API. Не переносить целиком систему старого проекта. Эта заметка фиксирует исследование; игровой overlay ещё не реализован.
